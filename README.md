# sim-eval-lab

**CARLA SIL 闭环仿真与仿真评测实验台。**

这个仓库回答一个问题：**当仿真里跑出一个"漂亮结果"，凭什么相信这个数不是仿真的伪影？**

不是算法仓库，不是工具教程。里面每一组实验都对应一个**判据级反例**——
同一条测试判据、同一个被测系统（SUT），只换被控对象，结论就反过来。

## 实验台形态（重要边界）

主实验用的是 **1-D 纵向台**：每 tick 跑完物理后把车**拉回出发点、保留速度**（跑步机法）。

- ✅ 纵向动力学**完全来自 CARLA**（踏板 → dv/dt 是 CARLA 算的）——要测的就是这个
- ✅ 无横向、无路口、无掉出路沿、不依赖地图
- ❌ **不测横向功能**（ALCA / LKA 类判据一律不适用）
- ❌ 无传感器模型 —— `distance` 是几何真值，不是雷达输出
- ❌ 无真空间碰撞 —— `gap < 0` 表示"算出来撞上了"，不是物理接触

⚠ 跑步机法会把**测点坡度冻在原地**（见反例 3）。任何用跑步机测出的稳态速度，
**必须同时报告测点位置和坡度**，否则数字不可迁移。

## 复现性约定

- **脚本 > 数据**：配图由脚本生成，不存截图。
- **数据入库**：只入 json / csv / log（约 4 MB），不出图；图由脚本重画。
- **大文件不入库**；CARLA 本体不随仓库分发。
- 复现步骤、版本、测点坐标见 [`carla-demo/README.md`](carla-demo/README.md)。

## 环境

CARLA 0.9.15（Windows 原生）· Python 3.11 · numpy / pandas / matplotlib。
SUT 通过环境变量 `ACC_SIM_DIR` 按路径导入，**不装到 site-packages**：

```bat
set ACC_SIM_DIR=D:\path\to\acc-sim
```
